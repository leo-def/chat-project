# Development Instructions for AI Agents - Chat Project

> Guidelines for AI-assisted development of the Android Chat Application.

## 🎯 Project Overview

- **Purpose**: Real-time chat application for Android users
- **Type**: Native Android app with Firebase backend
- **Tech Stack**: Kotlin, Android SDK, Firebase (Auth + Real-time DB)
- **Build**: Gradle with Android Studio

---

## 🏗 Architecture Pattern

**MVVM (Model-View-ViewModel)** with Repository pattern:
- **View Layer**: Fragments/Activities with Material Design UI
- **ViewModel**: State management and business logic
- **Repository**: Abstraction over Firebase and local storage
- **Model**: Kotlin data classes with Firebase annotations

### Core Components
```
UI Layer         - Fragments, Activities, Adapters
ViewModel Layer  - State, LiveData, business logic
Repository      - Firebase, local cache abstraction
Model Layer      - Message, User, Chat data classes
Firebase Layer   - Authentication, Real-time DB, messaging
```

---

## 📂 File Naming & Conventions

**Fragments**: PascalCase with `Fragment` suffix
- `ChatListFragment.kt`, `ChatDetailFragment.kt`, `AuthFragment.kt`

**Activities**: PascalCase with `Activity` suffix
- `MainActivity.kt`, `LoginActivity.kt`

**ViewModels**: PascalCase with `ViewModel` suffix
- `ChatViewModel.kt`, `AuthViewModel.kt`, `UserViewModel.kt`

**Repositories**: PascalCase with `Repository` suffix
- `ChatRepository.kt`, `AuthRepository.kt`, `UserRepository.kt`

**Adapters**: PascalCase with `Adapter` suffix
- `MessageAdapter.kt`, `ChatListAdapter.kt`

**Data Classes**: PascalCase with `@JsonClass` Firebase annotation
- `Message.kt`, `User.kt`, `Chat.kt`

---

## ✅ DO's

1. **DO** use LiveData for reactive state management
2. **DO** implement Repository pattern for data abstraction
3. **DO** use Firebase listeners for real-time updates
4. **DO** validate user input before Firebase operations
5. **DO** implement proper error handling with Try-Catch

---

## ❌ DON'Ts

1. **DON'T** access Firebase directly from UI layer
2. **DON'T** perform long-running operations on main thread
3. **DON'T** hardcode API keys or Firebase credentials
4. **DON'T** make synchronous Firebase calls
5. **DON'T** skip authentication checks before data access

---

## 📋 Common Workflows

**Setting up Firebase authentication**:
1. Initialize Firebase in Application onCreate()
2. Create AuthRepository with Firebase Auth
3. Implement sign-up/sign-in methods
4. Store auth token securely
5. Create AuthViewModel for UI coordination

**Creating real-time message listener**:
1. Get chat reference from Firebase
2. Add ValueEventListener to messages node
3. Update ViewModel LiveData on data change
4. UI observers update RecyclerView automatically
5. Handle listener errors and detach appropriately

**Building message list UI**:
1. Create MessageAdapter extending RecyclerView.Adapter
2. Use DiffUtil for efficient updates
3. Bind Firebase data to list items
4. Handle item click and long-press actions
5. Scroll to latest message on new data

**Implementing typing indicators**:
1. Create "typing" node in Firebase for each chat
2. Set to true when user starts typing
3. Use debounce to prevent excessive updates
4. Listen to typing changes in other users
5. Display UI indicator for typing users
